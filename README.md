# relay-audit · 中转站模型真伪审计工具

本地运行的小工具：填一个中转站的 **Base URL + Key**，拉取模型列表，一键把「这批模型到底是不是它标的名字」测出来。

- 零第三方依赖，只要求 Python 3.10+
- 纯本地，Key 只在内存里，不落盘、不联网上传
- 输出**风险分 + 证据链**（不是非黑即白的“真假”），并给出可存档的 HTML 报告

## 怎么用

1. 双击 `start.bat`（或 `python server.py 8737`）
2. 浏览器打开 <http://127.0.0.1:8737>
3. 填 Base URL / Key → 点「拉取模型列表」
4. 勾选要测的模型（默认自动勾上 deepseek / flash / haiku / mini 这类便宜货）
   - **必须至少选两个不同档位的模型**，点「＋参照组」可自动勾一个最便宜 + 一个最贵。同源判定是**聚类**出来的，不预设任何配对。
5. 设好预算上限 → 点「开始全测」
6. 跑完点「导出 HTML 报告」存档

> 建议：先在便宜模型上跑一遍确认流程，再放开贵的。**预算闸门默认开**（总调用次数 + 每模型调用次数 + 估算美元），超了会自动停。

## 七项检测器

| 检测器 | 原理 | 能抓到什么 |
|---|---|---|
| **模型名一致性** | 请求 `model` vs 响应 `model` | 换名（`opus-5` 回 `sonnet-5-5`）；支持配置合法别名 |
| **注入量** | 同一句 `hi` **采样 5 次**，看输入 token 分布 | 别人家的系统提示被塞进来（正常 <1000；异常 >4000）；并暴露“混池”：同一模型名随机在干净/套壳通道间跳（例：`27169/672/27170`） |
| **身份/系统提示** | 问“你是哪个模型”，再让它复述 system prompt | 自报 Kiro / Cursor / Trae 等；自称旧版本 |
| **流式结构** | `stream=true` 的事件序列与对象名 | 后端被换（Anthropic 的 `message_start…` vs OpenAI 的 `chat.completion.chunk`） |
| **Tokenizer 指纹** | 发 300 个 ASCII 字符、150 个汉字（`max_tokens=1`），取两次 `prompt_tokens` 的差值 | **参考项**（不是硬判据）：差值能抵消固定的系统提示，但注入量本身会随机波动，Δ 不稳定；只在两个模型 Δ/ratio 完全一致时才判同源 |
| **能力基准** | 5 道有确定答案的题（答案由本机 Python 现算） | 水平明显对不上宣称档位 |
| **采样一致性** | 同一题连问 3 次 | temperature=0 下应稳定；抖动过大说明后端不稳 |
| **链路层级** | 看响应里有没有“上一层的痕迹”：模型名是否厂商规范名、`usage` 是否混入 `credit_usage` 这类非厂商字段、响应头是否带 `oneapi/newapi`、错误文案是否“上游服务暂时不可用” | 区分 **自有号池（直销）/ 一层中转 / 中转的中转**；后者既吃 token 又降质量 |
| **动态题（AI）** | 用便宜模型现场出题 + 判卷 | 防止被“背题库”的中转站识别成测试流量 |

另外还有一层**跨模型检测**：如果两个不同模型名给出**完全相同**的答案向量（包括相同的错误值），会被标记为「疑似同一后端换名」——这是识破“opus 其实是 sonnet”最有力的一招。

## 风险分怎么读

| 分数 | 结论 | 含义 |
|---|---|---|
| 0–20 | 暂未发现问题 | 协议、成本、能力都对得上 |
| 21–50 | 需注意 | 有单项异常，建议人工复核 |
| 51–75 | 高风险 | 多项异常叠加，不建议用于重要工作 |
| 76–100 | 极可能造假 | 换名 / 注入 / 身份暴露同时出现 |

分数只是排序工具，**证据链才是结论**。合法中转站也会做别名映射、也会加系统提示，遇到这类情况应看「合法别名」提示而不是直接判死。

## 为什么不做“配对假设”

早期版本内置过“opus→sonnet”的固定配对。那只是把某个案例的答案写死：遇到
“claude 其实是 deepseek 套壳”“gpt 其实是 glm”就会失效，本质上是带着结论找过程。

现在改成两条**与型号名无关**的通用机制，只依赖“被测站点内部的模型互相比较”：

1. **Tokenizer 指纹聚类**：不看名字，只比分词器差值；两个名字不同、指纹相同 → 同一后端。
2. **答案向量聚类**：所有被测模型跑同一套题，按答案向量分组；连错误值都相同 → 同一后端。

所以正确的用法是**至少选两个不同档位的模型一起测**，让工具去聚类，而不是预设谁对应谁。

## 基准指纹库

先用官方/可信端点录一次签名，之后拿任意中转站来比对“它到底最像谁”：

```powershell
python engine.py record official-claude-sonnet-5 https://api.anthropic.com sk-ant-xxx anthropic claude-sonnet-5
python engine.py record official-deepseek-v4     https://api.deepseek.com/v1 sk-xxx openai deepseek-chat
```

签名存 `baselines/*.json`（答案向量、tokenizer、served、注入样本）。此后每次审计自动比对：
**答案最接近哪个基准**；若最接近的基准与它自称的型号不一致 → 判定冒名（例如“自称 claude，答案却最像官方 deepseek”）。

## 已知局限

- **黑盒探测**：无法证明“就是官方那台机器”，只能证明“不是你以为的那个模型”。
- **Tokenizer 指纹是参考项**：中转站的注入量会随机波动，导致差值不稳定；只有在两次指纹**完全一致**时才判同源，否则不作为证据。
- **单次会骗人**：有些站按请求随机走真/假通道（本工具已尽量多次采样，但样本仍有限）。
- **长上下文 / 多模态**暂未纳入 v1（成本高、耗时长），后续可加 `needle-in-haystack` 和图片测试。
- 价格表只用于**估算**花费，不参与真伪判定。
